# Accessibility and personal agency

The person using the computer should be able to choose an approval workflow that works for them. Some people want confirmation for individual actions. Others need to avoid repeated dialogs or interactions that are physically difficult, slow, or unreliable.

Design goals:

- Keep a text-first path available.
- Use short explanations and stable action labels.
- Do not communicate status through color or images alone.
- Give demos a text equivalent.
- Make mode choice, affected resources, errors, and recovery understandable.
- Preserve the owner's choice without claiming that all operating-system or application prompts can disappear.

This repository does not include its own speech-recognition system or a complete computer-use agent. It supplies an approval layer and a setup prompt for use with an existing harness and its tools.

Assistive-technology compatibility is not assumed. Feedback about voice, keyboard, switch, eye-gaze, and other workflows is useful, but contributors do not need to share a diagnosis or other medical information. Describe the interaction, expected outcome, and obstacle.
