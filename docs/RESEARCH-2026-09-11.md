# Repository discovery and launch research

Research date: 2026-09-11. The question was how to present an accessibility-focused AI approval project so people can understand, find, try, and share it. This is a dated snapshot, not a promise of virality.

## Evidence and decisions

GitHub's README guidance centers what a project does, why it is useful, how to start, where to get help, and who maintains it. HandsFreeBridge therefore opens with the accessibility problem, owner-selected modes, a setup prompt, a harmless demonstration, and honest platform limits. The detailed development archive remains available below that entry point. [GitHub README guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)

Topics help people browse related repositories. The proposed topics describe actual scope: accessibility, assistive-technology, ai-agents, computer-use, human-in-the-loop, python, macos, and mcp. There is no evidence here that a particular topic produces a ranking boost or a predictable number of stars. [GitHub topics](https://docs.github.com/articles/classifying-your-repository-with-topics)

GitHub supports a custom social preview image. Its guidance recommends a 1280 by 640 image, under 1 MB. An eventual preview should show the project name, owner choice, and the actual prompt/demo. No fabricated usage counter or testimonial belongs in it. A custom image was not uploaded as part of this publication. [GitHub social previews](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview)

A license, contribution guidance, and conduct rules make expectations visible. The owner selected Apache 2.0. This only covers material the project can license; provider-owned snapshots without verified redistribution rights are represented by source pointers. [Starting an open-source project](https://opensource.guide/starting-a-project/), [GitHub licensing guidance](https://docs.github.com/articles/licensing-a-repository), [third-party notices](../THIRD_PARTY_NOTICES.md)

## Names considered

ClickOptional, OwnTheClick, HandsFreeBridge, AgencySwitch, and AgentOnYourTerms were offered. The owner selected **HandsFreeBridge**, repository slug `handsfree-bridge`.

Repository search and account-specific availability checks did not find an existing exact selected slug under the publishing account at the time of checking. This is not trademark clearance, domain availability, or proof that nobody elsewhere uses the name. One earlier candidate, OwnerMode, was dropped after a closely related agent-skills repository appeared.

## Practical launch plan

1. Publish the sanitized code, reusable prompt, license, tests, limits, and archive together.
2. Use a short description centered on owner control and fewer required interactions.
3. Make the demo reproducible without credentials or changes to a live machine.
4. Invite reports about specific interaction barriers and proposed adapters. Do not require medical details.
5. After real users test it, document measured outcomes and their consented feedback. Share only in relevant communities that permit project posts, with an explanation of affiliation.

Only repository publication and metadata are part of this task. No outside promotional messages, automated stars, paid engagement, or unsolicited outreach were sent.

## Method and limits

Research used DeepAPI web discovery, direct primary-page retrieval, repository detail retrieval, and two separate Blackboard/Scout reviews. Both Scouts completed. Primary GitHub guidance and repository metadata were checked directly rather than relying only on Scout claims. Full operational request identifiers and raw provider responses remain in private provenance records because they are unnecessary for public reuse.

This research supports clearer presentation and discoverability. It does not demonstrate a causal recipe for virality, guarantee adoption, certify accessibility, or verify every integration. Usage should be earned through working software and useful contributions.
